Coverage gate in practice

  • Fails closed: no tests = 0% = blocked

Lessons learned

  • Spec first pays off. The expected-outcomes table written in Task 1 became the integration-test oracle in Task 5 — the pipeline matched it on the first run.
  • Design the sample data into the rules. Every fraud weight was tuned so the 8 sample records exercise every decision branch (a rejection exactly at threshold 70, flags at 35/40/50).
  • Changing stacks is cheap when the spec is the contract. Switching Python → Node.js + React was a one-document revision, then regeneration.
  • Hooks beat discipline. A coverage gate that fails closed caught its first push the same day it was written.
  • MCP is two-way. context7 fed docs into code generation; the custom FastMCP server exposes the pipeline back to the AI — the workflow both consumes and produces MCP.
  • Environment quirks are real work: corporate npm registry, Node 18 vs 20 (undici needs the File global), sandboxed networking — all documented in HOWTORUN/research notes.
